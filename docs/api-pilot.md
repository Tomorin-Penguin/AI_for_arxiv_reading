# 10篇论文的API云端试验

用户已授权这一次试验的**模型调用总预算不超过5美元，最多10篇，2路并发**。
这是一次试验，不是新的每日付费任务；现有11:00阅读及14:00–16:30邮件任务不变。

## 用户只需完成的设置

1. 在 [OpenAI API计费页面](https://platform.openai.com/account/billing/overview) 完成API计费设置。
   5美元是本试验的模型调用上限，不是承诺的充值最低额，也不包括GitHub运行费用。
   不需要为试验另买服务器；先使用GitHub Actions。私人仓库的额度及可能的超额费用以账户页面为准。
2. 在 [API密钥页面](https://platform.openai.com/api-keys) 为这个用途创建专用密钥。
   如需选择项目，可以新建 `arxiv-reading`。密钥不要发到聊天或写入仓库文件。
3. 打开仓库 Settings → Secrets and variables → Actions → New repository secret。
   Name填写 `OPENAI_API_KEY`，Secret填写密钥，保存后仅告知“密钥已配置”。

实现准备和离线测试完成后，助手负责合入试验流程、运行、检查和反馈。
本变更以草稿PR准备；尚未合并、尚未启动任何模型调用。

## 运行与检查

工作流名为 `arXiv API pilot (10 papers, USD 5 maximum)`，只有手动触发，默认 `prepare`。
合入默认分支后，先完成来源准备，检查最新的已读记录，再运行 `paid`，确认字段为
`RUN_10_PAPERS_MAX_USD_5`。不能因为运行失败就重复点击重新运行。

试验从已通过预分类、没有已读记录或阅读卡的论文中，按固定随机种子选10篇，尽量覆盖两个板块。
当前配置引用2026-10-28公告批次；这不是执行当天新论文。报告同时显示公告日期与实际执行时间。
选样发生在实际运行时，避免把今天已经补读的文章再次付费阅读。
在与现有云端阅读同时运行前，应选择没有活跃阅读者的时段，或先协调暂停相同队列；本试验不会自动修改旧任务。

论文标题、完整作者摘要、版本、正文、来源、内容哈希一并保存。
正文按顺序获取，相邻请求至少3.1秒，模型阅读并行2篇。
优先HTML并保留公式的TeX替代文本，必要时提取PDF文本。
PDF图像、图表视觉内容和提取异常不算已检查。正文过长或缺失时停止，不能截短后声称全文已读。

每篇生成摘要翻译、独立双语概括、正文证据、局限、I/R评分和具体下一步。
证据短句自动核对是否出现在正文、是否仅来自摘要；位置及物理解读仍需人工/助手抽检。
阅读草稿不自动加入正式已读账本，也不自动触发邮件。通过抽检后再决定是否纳入正式结果。
中文简报与双语精选从阅读卡汇编，不产生额外的模型调用。

## 费用与失败处理

- 固定 `gpt-6.1-sol`、Standard、medium推理；记录每篇输入、输出、缓存及推理用量。
- 费率核验于2026-10-29，过期后拒绝付费执行。长期上线前重新核价。
- 发送正文前调用官方输入计数接口，完整统计指令、正文和输出格式。
- 按最贵输入费率（包括缓存写入）及最大输出量预留；输出限制包含推理token。
- 所有并发调用共享一份加锁的预算账本；已支出加在途预留不得超过5美元。
- 请求超时或费用无法确认时，保留预留并停止新请求，不盲目重试。已经在途的另一篇可能继续完成。
- GitHub在付费调用前原子创建 `api-pilot-20261029-used` 分支作为永久占用标记。
  已存在标记、重复工作流或同一运行的重跑都不能获得新的5美元。不要删除该分支来绕过保护。
  若失败发生在占用之后，先核对账单与日志，再决定是否授权剩余额度内的恢复。
- 该分支只作试验占用标记，结果在Actions运行的artifact中保存30天；应及时归档报告与费用日志。
- 价格和用量计算不是服务商账单。额外服务、其他程序调用、税费及GitHub费用不在此模型预算内。

## 验收

检查10篇的成功数、正文证据与双语一致性、总时长、逐篇费用、失败率；
选2–3篇与原文逐节核对。只有实测后才推算全量任务是否能在1–2小时完成以及月度费用。
首次试验失败时允许不足10篇完成，但必须报告具体原因，不能通过隐瞒失败或重复调用凑齐。
